# BitBlock — Channel Plan

> **CODE. CREATE. EXPLORE.**

BitBlock is a faceless creator-led channel about technology, software development, gaming, and the curiosity that connects them. This repository is the long-term handoff document for the channel: its purpose is to let a future AI agent, collaborator, or the creator continue the work without having to reconstruct decisions from old chats.

## Start here

1. Read [the channel overview](docs/CHANNEL_OVERVIEW.md) for the identity, purpose, audience, and overall direction.
2. Read [the content strategy](docs/CONTENT_STRATEGY.md) for the channel's two main content worlds.
3. Read [the editorial principles](docs/EDITORIAL_PRINCIPLES.md) before proposing or scripting a video.
4. Read [the production workflow](production/WORKFLOW.md) before planning a shoot, timelapse, voiceover, or edit.
5. Read [the current priorities](planning/NOW_NEXT_LATER.md) to understand what is active and what is deliberately deferred.

## Important decisions already made

- **One umbrella channel first:** publish under BitBlock rather than splitting into BitBlock Gaming and BitBlock Tech immediately.
- **Two broad content worlds:** Tech includes general technology and development; Gaming includes Minecraft and other games.
- **ATLAS is a flagship Tech series:** document its development session by session.
- **Timelapse method:** use periodic screenshots (roughly every 5–10 seconds as a starting point), turn them into a timelapse, and add a full voiceover for each episode.
- **Planning videos belong in the ATLAS journey:** planning and development can be separate episode types within one series.
- **Faceless does not mean personality-free:** narration, decisions, experiments, mistakes, and explanations provide the human perspective.
- **Quality and sustainability matter more than arbitrary upload frequency:** the plan should support school, project work, and real life.

## Status and change policy

This repository records the current working direction, not an unchangeable contract. Ideas can be revised when testing, experience, or the creator's preferences justify it. Mark a decision as provisional when it has not been tested. Never claim a video was recorded, uploaded, or completed unless the creator confirms it.

When updating this repository:
- Inspect the existing files and preserve useful decisions.
- Keep one clear source of truth for each topic.
- Update links when files move.
- Prefer focused files over one enormous document.
- Do not add files just to increase the file count.
- Do not silently turn suggestions into confirmed decisions.
- Explain meaningful changes in commit messages.

## For future agents

Start with this README, then read [Agent Handoff](planning/AGENT_HANDOFF.md). Treat the creator as the decision-maker. Help with strategy, research, scripts, technical verification, production planning, titles, descriptions, and iteration. Be practical and collaborative; avoid rigid corporate-style rules and unnecessary complexity.
